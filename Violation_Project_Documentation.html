Project Overview

The Violation Management Project is an internal initiative to systematically detect, validate, and action fraudulent activity within Involve Asia's affiliate network. The project categorises fraud into seven defined types, each with specific detection logic, and aims to build a repeatable process for both advertiser-reported and internally detected violations.

Fraud Handling Process Flow

End-to-end process covering how a fraud case is submitted, categorised by offer profile at ticket creation, and enforced with the appropriate controls. S1 cases are automatically set to Protection-Focused. For S2 cases, the profile from Mahadir determines the enforcement path. Growth-Focused cases skip the proof cycle entirely. Protection-Focused cases follow a full proof submission window before enforcement. Balanced cases: the Commercial team decides whether to request proof — it is not mandatory.

Two Delivery Phases Phase 1 is the current process — Mini Tools assigns tasks to the responsible teams (Compliance, Operations, Finance, Validation) who execute and verify completion within the system. Phase 2 is the automated state where Mini Tools applies all controls automatically and notifies stakeholders — no manual task assignment needed.
How Offer Profile Fits Into the Flow The Offer Profile is assigned at ticket creation, before any proof cycle begins. S1 cases are automatically set to Protection-Focused regardless of the offer's assigned profile — they bypass the profile check entirely. For S2 cases, the profile from Mahadir determines the enforcement path. Protection-Focused cases follow a full proof submission cycle with a 5-working-day window. Balanced cases: the Commercial team decides whether to request proof — it is not mandatory. Growth-Focused cases skip the proof submission and accept/reject stages entirely — since no enforcement is applied, there is no proof cycle. The ticket moves directly to monitoring and closed as a record.

The three profiles define who owns the enforcement decision and which teams are responsible:
  • Growth-Focused: Report and monitor only — no enforcement or punishment is applied. IA detects and records the violation; the case remains under monitoring. If the pattern poses damage to IA, the Commercial/Advertiser team is responsible for reassessing and retagging the offer to a higher enforcement profile (Balanced or Protection-Focused).
  • Balanced: Balances advertiser and IA interest, weighted slightly towards IA. The Commercial team decides enforcement boundaries and whether to request proof. Operations assists on financial controls — specifically, express and early payouts are blocked. No traffic block, no conversion rejection, no publisher ban. The Commercial team monitors all other aspects.
  • Protection-Focused: Serves the interest of the advertiser, potentially at the expense of IA performance. Full enforcement is owned by the Operations team. Finance team is required for payout controls, and the Validation team is required for conversion actions. All three teams — Ops, Finance, and Validation — are active participants.
  • S1 cases (any Offer Profile): Automatically set to Protection-Focused at ticket creation — the strictest controls apply regardless of what profile the offer was assigned. The Offer Profile check is bypassed for S1 cases.

Fraud Category Framework

Seven fraud categories have been defined for the Involve Asia affiliate network. Each category has a clear definition and a set of detection metrics used to identify violations.

Category 01
Porn / Gambling

Affiliate drives conversions from adult, porn, or gambling/betting sites that violate the advertiser's Terms of Service.

Detection Logic
Referrer domain classification:
  • Check referrer URL against a porn/gambling domain block list
  • Flag if referrer domain matches known adult/gambling category
Category 02
Cookie Stuffing / Cookie Dropping

The affiliate fires the advertiser's tracking cookie onto a user's browser without the user having clicked or seen any promotional placement.

Metric 1 — Multi-Offer Click Pattern
  • Flag conversions where multiple clicks are recorded across different offers from the same publisher
  • Time window: within 10 seconds (±5s from click timestamp) for a single user
Metric 2 — Click Source Type
  • Check if the single click source originates from an IMG tag or iFrame
  • IMG/iFrame-triggered clicks indicate invisible, user-unaware cookie firing
⚠ Note: Both metrics should be combined to confirm Cookie Stuffing. Either metric alone may not be sufficient to flag a violation.
Category 03
Pop-Under / Pop-Up

Traffic generated by forced pop-up or pop-under windows on low-quality or pirated-content sites. Most programs explicitly prohibit pop traffic.

Detection Logic
Both conditions must be met:
  • Conversion Rate (CR) < 0.5%
  • Total clicks > 100,000 per month
  • Offer's promotional method filter: Pop-Up, Pop-Under & Tab-Under only
Category 04 ⚠ Work in Progress
Illegal Direct Link

Affiliate funnels traffic straight to the advertiser's tracking URL, bypassing legitimate promotional placements.

Detection Logic
  • Identify click_ids with abnormally high conversion volume
  • Remove duplicate orders using item-level tracking (adv_sub1)
  • Threshold: > 20 unique adv_sub1 (Order IDs) per single click_id
Category 05 ⚠ Work in Progress
Brand Bidding

Bidding on a brand's trademarked keywords in search engine advertising when the brand's affiliate programme explicitly prohibits this.

Detection Logic
  • Referrer URL domain is a search engine: google.com, bing.com, yahoo.com
  • Cross-check offer's approved promotional method — must not include SEM/Search
Category 06 ⚠ Work in Progress
Empty Referrer URL

No referrer URL is recorded in clicks or conversions — traffic source is completely unknown and untraceable.

Detection Logic
  • Referrer URL field is empty or null in both click and conversion records
  • ⚠ No automated detection rule currently defined for this category
Category 07
Click Spam — Click Flooding

A publisher sends a massive volume of low-quality or bot-generated clicks to an affiliate link, artificially inflating click counts and attempting to steal last-click attribution from legitimate publishers.

T1 — Absolute Volume Trigger (Deterministic)
  • 800 clicks/min in any 1-minute window
  • Constant interval pattern (±100ms across ≥20 clicks)

SOP — Porn / Gambling Domain Blocking

Standard Operating Procedure for detecting and actioning affiliates that drive traffic from adult, porn, or gambling/betting sites that violate advertiser Terms of Service.

Scope This SOP applies to all violations where referrer domain analysis indicates traffic originating from adult, pornographic, or gambling/betting sites. It covers both advertiser-reported cases (S1) and internally detected cases (S2).
Mini Tools — Domain Blacklist (Module C) All domain blocking actions described in this SOP are managed through Mini Tools' Domain Blacklist module. Compliance submits the domain list to Kaishen via Mini Tools — not by direct email or manual tech ticket. For the weekly S2 cycle, Mini Tools pulls new candidates from Mahadir, cross-checks against the Trip.com advertiser-protected list, and generates the weekly change request (domains to remove + domains to add) for Kaishen to execute.

S2 — Internal Detection (Current State)

Weekly automated detection run — no enhancement enabled.

1
System (Automated)
Weekly Detection Run
System checks all referrer URLs against the known porn/gambling domain list. Runs once per week.
2
Mini Tools — Smart Assist
Pull New Domain Candidates from Mahadir
Mini Tools automatically pulls the top new domain candidates from Mahadir — those with the highest blocked click activity not yet on the block list. Domains that already appear on the Trip.com advertiser-protected list are excluded from the candidate list.
3
Compliance Team
Weekly Rotation — Remove & Add
Compliance reviews the candidate list in Mini Tools. Bottom-performing internal domains (lowest blocked click volume) are flagged for removal. Top new candidates from Mahadir are flagged for addition. Trip.com advertiser-protected domains are never removed.
4
Compliance Team → Kaishen
Submit Weekly Change Request via Mini Tools
Mini Tools generates a weekly change request listing domains to remove and domains to add. Compliance approves and submits via Mini Tools — no manual email. Kaishen executes the changes on the platform and confirms.
5
Compliance Team
Review Click Impact
Compliance monitors the impact of domain blocking via Mini Tools click impact reports — total clicks, blocked clicks, and block rate by publisher and offer. Top 5 publishers and offers by blocked volume are tracked weekly.
Limitation — Current State Block list rotation is weekly. Domains not surfaced in Mahadir's top candidates may be missed. No proactive crawling or real-time classification of new unknown domains.

Recommendations & Next Steps

Based on the validation study and framework review, the following improvements are recommended, ordered by priority.

1

Fix Mixed Promo Method Logic for Pop Detection

Update the detection rule so that if Pop is listed as ANY one of an offer's promotional methods (not just the sole method), it triggers the Pop detection check. This will recover the 8 cases currently being missed due to multi-method offers like "Social + Pop".

High Priority
2

Decouple CR Threshold from Publisher-Level Pop Detection

When a publisher is registered or confirmed as a Pop-traffic source, do not rely solely on the CR < 0.5% threshold to trigger detection. Publisher type should be a primary flag — if the publisher is known Pop, flag regardless of CR. This addresses the 6 offer combinations currently bypassing detection due to CR > 0.5%.

High Priority
3

Define Detection Rule & SOP for Empty Referrer URL

Currently the only category with zero automated detection. Define a minimum threshold (e.g., > X% of conversions with empty referrer), build an alert, and create a formal SOP for investigation and escalation.

High Priority
4

Enable Enhanced S2 Detection (Auto-Crawl)

The enhanced internal detection state (auto-crawl and real-time block list) is planned but not yet enabled. This would remove the weekly delay and extend coverage beyond the weekly top 20 block list. Prioritise infrastructure setup and testing for the Porn / Gambling category first.

Medium Priority
5

Write SOPs for Remaining 4 Categories

Cookie Stuffing, Pop-Under/Pop-Up, Illegal Direct Link, and Brand Bidding each need formal SOPs with defined roles (commercial vs tech), escalation paths, and enforcement actions. Use the Porn / Gambling SOP as the template.

Medium Priority
6

Run Validation Studies for Remaining Categories

Replicate the Pop Ads validation methodology for Cookie Stuffing, Brand Bidding, and Illegal Direct Link. Build test case datasets and measure true positive / false negative rates to identify further detection gaps.

Lower Priority
