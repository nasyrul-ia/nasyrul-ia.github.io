Introduction

Why We Need This System

As our affiliate network grows in volume, manual oversight of conversion data is no longer sustainable. This system introduces three automated monitoring modules that run daily, surface anomalies instantly, and publish findings to a shared Google Sheet — so the team spends time fixing issues, not finding them.

Module 01

High Sale Amount

Flags any Pending or Yet-to-Consume conversion exceeding MYR 200K. If the offer has approved records ≥ MYR 200K in the last 90 days, a 1.5× dynamic threshold is also applied as an additional check.

Module 02

Offer CVR Monitoring

Tracks click-to-conversion rate per offer against a 30-day baseline, alerting at 90%, 70%, and 50% drop thresholds — with active and affected publisher count per flagged offer.

Module 03

Publisher CVR Monitoring

Drill-down into individual publisher CVR when Module 2 flags an offer. The affected-to-active publisher ratio classifies the issue as Systemic, Mixed, Isolated, or Single Point — directing the right escalation path.

🗂 Master Tab — Combined Daily Summary (All Modules, All Offers)

A single Google Sheet tab that gives a full network-wide view at a glance — one row per offer, with High Sale Amount and CVR status side by side. Flagged cells are highlighted so issues are immediately visible without switching tabs.

⚙️ How Detection Works
CVR = Total Conversions ÷ Total Clicks  (per Offer, per Day — 1 Day Lag)
📊 Dual-Metric Status (Option C)
Status (vs 30D) Current CVR ÷ 30-day rolling average. This is the primary long-term health indicator — reflects sustained performance trend.
Status (vs 7D) Current CVR ÷ 7-day rolling average. This is the early-warning layer — catches sudden drops or recoveries before they show up in the 30D baseline.
💡 When the two statuses diverge: a 30D=Normal + 7D=Warning signals a recent sudden drop to investigate; a 30D=Warning + 7D=Normal suggests CVR is stabilising or recovering.

30-Day Baseline

Calculate average daily CVR per offer over last 30 days. This is the Normal (100%) reference.

7-Day Check

Calculate 7-day average CVR. A drift here is an early signal before current CVR becomes critical.

Classify Current CVR — Two Independent Status Metrics

Status (vs 30D): Divide current CVR by the 30-day baseline. This gives the long-term health status.
Status (vs 7D): Divide current CVR by the 7-day average. This acts as an early-warning layer — a divergence (e.g. 30D=Normal but 7D=Warning) signals a sudden recent drop that the 30D baseline hasn't absorbed yet, prompting earlier investigation.

Publisher Impact Count

Count active publishers per offer. Show how many (and what %) are also affected by the drop. If the ratio of affected to active publishers is below 90%, the issue may be publisher-specific — refer to Module 3 (Publisher CVR) for a full drill-down by publisher.

3

Publisher CVR Monitoring

Drill-down into individual publisher performance when an offer is flagged by Module 2
🟢
Triggered by Module 2 — Not a Standalone Module
This module only activates when an offer in Module 2 (Offer CVR) reaches Concern tier or above. The system then pulls publisher-level CVR data for that specific offer — allowing the team to determine whether the drop is a broad offer-side issue or isolated to specific publishers.
📐 Affected Ratio — Triage Diagnostic

The ratio of Affected Publishers ÷ Active Publishers is the primary diagnostic signal. The higher the ratio, the more likely the problem is on the offer or advertiser side rather than publisher-specific.

Affected / Active Classification Signal Recommended Action
≥ 90%
(e.g. 9/9)		 Systemic All or nearly all publishers affected — strong indication of an offer-side or advertiser-side problem (tracking broken, LP down, offer terms changed). AM escalates to advertiser immediately
50–89%
(e.g. 5/9)		 Mixed Majority affected — possible offer issue affecting certain traffic segments, or a cluster of publishers sharing a common geo, sub-ID, or traffic source. Check patterns across affected publishers; investigate both offer and publisher sides
10–49%
(e.g. 2/9)		 Isolated Minority affected — issue is likely publisher-specific (traffic quality, sub-ID problem, integration error on publisher end). Integration Team contacts specific affected publishers directly
1 Publisher Single Point Single publisher driving the offer's CVR drop — all others performing normally. Isolate and investigate that publisher only. Deep-dive single publisher; consider temporary pause pending investigation

⚙️ How Module 3 Works

Triggered by Module 2 Flag

When Module 2 classifies an offer as Concern, Warning, or Critical, Module 3 automatically generates a publisher-level CVR breakdown for that offer. Only flagged offers produce a Module 3 report — it does not run on clean offers.

Individual Publisher Baseline

For each active publisher on the flagged offer, the system calculates their own 30D and 7D average CVR. Each publisher has their own personal baseline — independent of the offer-wide average.

Apply Same Dual-Metric Status

Each publisher receives a Status (vs 30D) and Status (vs 7D) using the same four-tier classification (Normal / Concern / Warning / Critical) as Module 2 — calculated against their own individual baseline, not the offer-wide average.

Calculate Affected Ratio & Classify

Count publishers with any non-Normal status. Divide by total active publishers to get the affected ratio. Classify as Systemic (≥90%), Mixed (50–89%), Isolated (<50%), or Single Point (1 publisher). This classification directly drives the escalation path in the SOP.
